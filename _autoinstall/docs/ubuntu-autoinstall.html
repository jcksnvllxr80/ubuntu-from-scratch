Ubuntu Autoinstall/ Overview
Ubuntu 22.04 Edge Deploy Jammy
Full Pipeline

Build once.
Deploy anywhere.

Autoinstall builds a golden VM. That VM is sysprep'd, compressed, and stored. A factory utility transfers and installs it directly onto target hardware. Customer packages arrive post-deployment via nightly apt.

Pipeline

01 — VM BUILD
Autoinstall
Unattended install on local VM. Pulls base packages. Runs firstboot.
02 — CLEAN
Sysprep
Remove SSH host keys, machine-id, logs, cache. Shut down. Do not reboot.
03 — STORE
Compress
qcow2 → raw → xz. Push to artifact store. Single versioned artifact.
04 — DEPLOY ⚠ TBD
Factory Utility
Connects to target server. Transfers image. dd's to disk. Reboots.
05 — LIVE
Server Up
Boots into golden state. Network reaches artifact store.
06 — NIGHTLY
apt Update
unattended-upgrades pulls customer packages from artifact store.
07 — AUTO
postinst
Customer .deb postinst applies site-specific config automatically.

Key Principles

🖼
One Golden Image
The same compressed image is deployed to all servers regardless of customer. No per-customer image builds.
🧩
Variance in Packages
Customer-specific config lives entirely in .deb postinst scripts. The image itself is dumb.
🔁
Nightly Delivery
Customer packages aren't on the image at deploy time. They arrive post-deployment via unattended-upgrades.
🧹
Sysprep Before Compress
Every deployed server gets a unique machine-id and SSH host keys. Sysprep ensures the image doesn't carry build VM state.

Component 1

user-data YAML

Drives the unattended install on the build VM. Identical for all deployments.

Section Reference

SectionWhat It Does

networkDHCP on eth0 at install time
storageLVM layout — use name: direct to skip LVM
identityBaseline hostname, username, SHA-512 hashed password
sshInstalls openssh-server, injects pubkey, disables password auth

Full YAML

autoinstall/user-data
#cloud-config
autoinstall:
  version: 1
  locale: en_US.UTF-8
  keyboard:
    layout: us

  network:
    network:
      version: 2
      ethernets:
        eth0:
          dhcp4: true

  storage:
    layout:
      name: lvm

  identity:
    hostname: edge-server
    username: admin
    password: "$6$rounds=4096$salt$hash"  # mkpasswd -m sha-512

  ssh:
    install-server: true
    authorized-keys:
      - "ssh-ed25519 AAAA... your-key"
    allow-pw: false

  packages:
    - curl
    - wget
    - htop
    - ca-certificates
    - unattended-upgrades

  apt:
    sources:
      internal-pkg-store:
        source: "deb [trusted=yes] https://your-artifact-store/repo jammy main"

  late-commands:
    - curtin in-target --target=/target -- systemctl disable snapd
    - curtin in-target --target=/target -- apt-get purge -y snapd ubuntu-advantage-tools
    - curtin in-target --target=/target -- apt-get autoremove -y
    - cp /cdrom/firstboot/firstboot.sh /target/usr/local/sbin/firstboot.sh
    - chmod +x /target/usr/local/sbin/firstboot.sh
    - cp /cdrom/firstboot/services/firstboot.service /target/etc/systemd/system/firstboot.service
    - curtin in-target --target=/target -- systemctl enable firstboot.service

  user-data:
    disable_root: true

Component 3

First Boot

Runs once on the build VM after autoinstall. Hardens SSH, installs base packages, configures nightly apt. Disables itself — never runs again.

firstboot.sh

firstboot/firstboot.sh
#!/bin/bash
set -euo pipefail
LOG=/var/log/firstboot.log
exec > >(tee -a "$LOG") 2>&1

echo "[firstboot] Starting $(date)"

# ── Install base packages ─────────────────────────────────────
apt-get update -qq
apt-get install -y base-tooling

# ── Harden SSH ────────────────────────────────────────────────
sed -i 's/#PermitRootLogin.*/PermitRootLogin no/' /etc/ssh/sshd_config
sed -i 's/#PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
systemctl restart sshd

# ── Configure unattended-upgrades ────────────────────────────
cat > /etc/apt/apt.conf.d/50unattended-upgrades <<EOF
Unattended-Upgrade::Allowed-Origins {
    "your-artifact-store:jammy";
};
Unattended-Upgrade::Automatic-Reboot "false";
EOF

cat > /etc/apt/apt.conf.d/20auto-upgrades <<EOF
APT::Periodic::Update-Package-Lists "1";
APT::Periodic::Unattended-Upgrade "1";
EOF

systemctl enable unattended-upgrades
systemctl start unattended-upgrades

# ── Disable self ───────────────────────────────────────────────
systemctl disable firstboot.service

echo "[firstboot] Done $(date)"

firstboot.service

firstboot/services/firstboot.service
[Unit]
Description=First boot provisioning
After=network-online.target
Wants=network-online.target
ConditionPathExists=/usr/local/sbin/firstboot.sh

[Service]
Type=oneshot
ExecStart=/usr/local/sbin/firstboot.sh
RemainAfterExit=yes
StandardOutput=journal+console

[Install]
WantedBy=multi-user.target
Golden Image Step 1

Sysprep

After firstboot completes, clean all machine-specific state before imaging. Every deployed server must come up with its own unique identity.

⚠ CRITICAL — SHUT DOWN AFTER SYSPREP, DO NOT REBOOT Rebooting after sysprep regenerates the state you just cleaned. Run sysprep, shut down immediately, then image the disk.

sysprep.sh

sysprep/sysprep.sh — run inside VM before shutdown
#!/bin/bash
set -euo pipefail

echo "[sysprep] Starting $(date)"

# ── SSH host keys — regenerated on first boot ─────────────────
rm -f /etc/ssh/ssh_host_*

# ── machine-id — must be unique per deployment ────────────────
truncate -s 0 /etc/machine-id
rm -f /var/lib/dbus/machine-id
ln -s /etc/machine-id /var/lib/dbus/machine-id

# ── Logs ──────────────────────────────────────────────────────
find /var/log -type f -exec truncate -s 0 {} \;

# ── apt cache ─────────────────────────────────────────────────
apt-get clean

# ── Shell history ─────────────────────────────────────────────
unset HISTFILE
rm -f /root/.bash_history /home/*/.bash_history

# ── Temp files ────────────────────────────────────────────────
rm -rf /tmp/* /var/tmp/*

echo "[sysprep] Done — shut down now, do not reboot"
run sysprep then shut down immediately
sudo bash sysprep.sh && sudo shutdown -h now

What Regenerates on First Boot

Item CleanedWhat Regenerates It on Deployed Server
SSH host keysRegenerated automatically by ssh service on first boot
machine-idRegenerated automatically by systemd-machine-id-setup
Logs / cache / tmpRebuilt organically as services start
Golden Image Step 2

Compress & Store

Convert the sysprep'd VM disk to a raw image, compress it, and push to your artifact store. This is the deployable artifact.

Convert, Compress, Push

bash
# 1. Convert qcow2 → raw
qemu-img convert -f qcow2 -O raw disk.img disk.raw

# 2. Compress
xz -T 0 -v disk.raw       # produces disk.raw.xz — best ratio, uses all CPU threads
# or faster:
gzip -v disk.raw           # produces disk.raw.gz

# 3. Push to artifact store
aws s3 cp disk.raw.xz s3://your-artifact-store/images/edge-server-latest.raw.xz

# 4. Verify
aws s3 ls s3://your-artifact-store/images/
ℹ COMPRESSION RATIO A typical minimal Ubuntu server image (~2-4 GB raw) compresses to ~500 MB–1 GB with xz. xz -T 0 uses all available CPU threads — use on the build machine, not on constrained hardware.
Deploy

Factory Utility ⚠ TBD

Connects to the target server, transfers the compressed image and install script, and executes the install remotely. Approach is defined — implementation details are not yet finalised.

⚠ TBD — OPEN QUESTIONS BELOW The flow and scripts below represent the confirmed approach. Items marked TBD require decisions before implementation.

Confirmed Flow

1
Factory workstation connects to target server
Target server is running some OS that accepts SSH. Factory workstation SSHs in.
2
Transfer compressed image + install script
SCP or rsync from workstation to target. install.sh and the compressed image land on the target.
3
Execute install.sh remotely over SSH
Workstation triggers install.sh on the target. Script runs: decompress → dd to disk → reboot.
4
Server reboots into golden state
Server comes up from the installed image. Network reaches artifact store. Nightly apt takes over from here.

install.sh — runs on target server

factory/install.sh
#!/bin/bash
set -euo pipefail

IMAGE_URL="https://your-artifact-store/images/edge-server-latest.raw.xz"
TARGET_DISK="/dev/sda"       # ⚠ TBD — confirm per hardware platform

echo "[install] Downloading image..."
curl -fSL "$IMAGE_URL" -o /tmp/image.raw.xz

echo "[install] Writing to $TARGET_DISK..."
xz -dc /tmp/image.raw.xz | dd of="$TARGET_DISK" bs=4M status=progress conv=fsync

echo "[install] Rebooting..."
reboot

Factory Workstation Script

factory-provision.sh — runs on workstation
#!/bin/bash
TARGET_HOST="$1"              # e.g. 192.168.1.50
SSH_KEY="~/.ssh/factory-key"

echo "[factory] Transferring install script..."
scp -i "$SSH_KEY" factory/install.sh admin@"$TARGET_HOST":/tmp/install.sh

echo "[factory] Executing install..."
ssh -i "$SSH_KEY" admin@"$TARGET_HOST" "sudo bash /tmp/install.sh"
usage
bash factory-provision.sh 192.168.1.50

Customer .deb postinst
All customer-specific setup runs here — hostname, service config, hardware interface params. Triggered automatically on install and upgrade.

Repo Auth
Bake a read-only credential or client cert into the image for unattended apt auth against a private store.
🔁
Reboot Policy
Define a maintenance window in unattended-upgrades or handle required reboots in postinst.
